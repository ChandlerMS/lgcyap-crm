# Signed In Google Sheets export

In Event Attendance, expand **Signed in** and choose **Export to Google Sheets** beside **Export CSV**. The export uses the same popup, Google identity verification, PKCE and temporary Drive file access as Applications. Choose the same Google account used to sign into the CRM. A successful export creates a new private native Google Sheet in that account’s Drive and returns an Open Google Sheet link.

Selected sign-in dates, office, name search, approval status and sort order are preserved in signed OAuth state. CSV, XLS and Google Sheets exports follow the same filtered list. The callback reads attendance again on the server and exports one row per matching recruit, including intermediate visits within the selected date range. Columns use the same field mapping as the existing CSV/XLS downloads: name, phone, email, office, recruiting stage, HubSpot ticket/link, sign-in count, first/latest sign-in and application time. Incomplete source reads or a different Google identity fail without creating a file.

The former monthly updater is retired. Its panel and Vercel schedule have been removed; its status/manual-sync, cron and notification endpoints return HTTP 410. Outstanding legacy Sign-Ins consent callbacks cannot start a sync. Existing Google files and stored historical sync state are retained. Applications monthly Sheets and its Google connection are unchanged.
