# Gmail template drafts

The owner selected **Open Gmail with the template filled in**. New Email will prepare an offer or custom message in the app, create a formatted Gmail draft in that employee's own Google mailbox, and open Gmail for final review and Send. Gmail is the delivery surface; the app does not send messages or log mail to HubSpot. Existing CRM-linked recipients remain verified against the source Contact and Ticket; this is CRM data access, not a HubSpot email connection.

Approach: use the Gmail Drafts API so the current branded HTML offer templates and inline logo survive. A plain Gmail compose link needs no OAuth but loses rich formatting. Direct in-app sending was offered and the owner chose Gmail instead. Request openid/email and gmail.compose in a separate explicit connection flow, with offline encrypted per-user credentials. No Gmail inbox-reading scope is requested. The Email panel opens the user's Gmail inbox externally rather than asking for a HubSpot received-mail channel.

The existing Google OAuth client/callback is reused without changing sign-in or Sheets scopes. Use a distinct state prefix/cookie, PKCE, short expiry, authenticated user binding, verified matching Google account and existing Google account subject binding. Store refresh tokens encrypted and never return tokens to the browser. Local disconnect removes only this Gmail connection and must not revoke Sheets or ordinary sign-in grants.

The composer offers current configured Licensed and Unlicensed templates, validates licensing route and required dates, allows a custom message, and requires a preview before creating a draft. Preview authorization binds the employee, verified recipient, template/content and expiry. Re-read recipient/template before draft creation; changed data requires a new preview. One request ID creates at most one draft. Persist intent before the provider request; never automatically replay an ambiguous request. Persist metadata only, not recipients or message bodies.

Gmail opens using the draft's thread link for the verified Google email, with a Drafts-folder fallback. The app never labels a draft as sent. Gmail API availability and the owner's Google consent are activation requirements; normal CRM sign-in remains independent. The current templates remain server-only production configuration, not copied into this public repository. Update the privacy notice for draft-management access and encrypted refresh-token storage.
