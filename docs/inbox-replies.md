# Inbox dashboard conversation replies

The Inbox card below the recruiting pipeline previews active HubSpot conversations on hover or keyboard focus. Each row's Open button reads that conversation and shows a plain-text reply composer inside the floating preview. Card links and Full Inbox links use the canonical `#inbox/thread/<id>` route. The previous `#inbox/<id>` route was not recognized and fell back to Dashboard.

Selecting a conversation keeps the preview open until Close preview, Escape or navigation. The preview stays mounted when hidden, so drafts and pending sends survive closing it. Drafts and uncertain-send blocks are retained per conversation when returning to the list. Sending requires an explicit Send reply click. Message history remains available independently of reply permission.

`POST /api/inbox-reply` supports `prepare` and `send`. Both require the CRM session, editor authorization, same-origin JSON requests and the existing production write capability. The server verifies private app `59264745` in HubSpot portal `50894788`, with `conversations.read`, `conversations.write` and `crm.objects.owners.read`. The employee's exact sign-in email must resolve to one active HubSpot owner's `userId`; the sender is that user's `A-` actor, never the owner ID or a browser-provided identity.

The server derives recipients, channel and channel account from the latest nonarchived MESSAGE. Supported channels are HubSpot live chat (1000), Messenger (1001) and email (1002). Other channels, including WhatsApp, require the native HubSpot interface. Preparation returns ten-minute signed reply details bound to the employee and current conversation. Send re-reads those details before POSTing. A changed message, recipient, channel or expired signature requires review of refreshed reply details. The existing metadata-only Postgres ledger prevents duplicate requests; no message body or address is written to it. Network ambiguity or failed acknowledgement blocks automatic resends and preserves the draft for checking in HubSpot. The guarantee is per request ID: navigating away from the dashboard clears drafts; manually composing a new reply afterward is a new operation. Demo mode hides live conversations, and pending-send state survives live/demo switches.

API reference: [HubSpot Conversations guide](https://developers.hubspot.com/docs/api-reference/conversations-conversations-v3/guide), [send a message](https://developers.hubspot.com/docs/api-reference/conversations-conversations-v3/public-message/post-conversations-v3-conversations-threads-threadId-messages), and [message sorting](https://developers.hubspot.com/docs/api-reference/conversations-conversations-v3/public-message/get-conversations-v3-conversations-threads-threadId-messages).
