# Automatic monthly application Sheets

Open Applications in the production CRM, signed in as **chandler@lgcyap.com**, and choose **Connect Google Sheets**. Choose that same Google account and allow file access. This is a one-time offline authorization, separate from CRM login and one-off exports. The chat's Google Drive connection cannot authorize a deployed server.

After consent, an initial full sync runs in the background. The panel shows the current month's Sheet and last successful check; Sync now performs a deliberate full repair. Existing manual Google Sheets/CSV/Excel exports still work independently.

## Setup

Use the existing production GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET, BETTER_AUTH_SECRET, BETTER_AUTH_URL, DATABASE_URL, HUBSPOT_ACCESS_TOKEN and CRON_SECRET. Enable both **Google Drive API** and **Google Sheets API** for that OAuth client's Google Cloud project. Allow `https://www.googleapis.com/auth/drive.file` through Workspace controls if required. The flow reuses the existing registered callback `https://crm.lgcyap.com/api/auth/callback/google` with a distinct `application-sheets.` state prefix. No new callback registration is needed. A Google consent screen left in external Testing mode can expire refresh tokens after seven days; use an appropriate internal/published configuration for sustained background access.

The additive migration `0015_application_sheets.sql` initializes lazily after request authorization. It stores an encrypted refresh token, monthly file IDs/fingerprints, last-success/error state, and a bounded job lease. Keep BETTER_AUTH_SECRET stable; reconnect Google Sheets after changing it.

## Timing and source

The Sheets update **once each morning at 9 am America/New_York**. Production Vercel cron `/api/cron/application-sheets` is called every 15 minutes from 13:00 to 15:45 UTC with CRON_SECRET bearer authorization, which covers 9 am Eastern in both standard and daylight time. The first call at or after 9 am Eastern reads the same HubSpot application notes as the Applications page. Calls before 9 am, and calls after that day's run has succeeded, return `waiting` without reading HubSpot. No browser or signed-in session needs to remain open.

The morning run writes only the months with new or changed information since the last update: a new submission, a stage change, an Approve/Deny decision, or an edit to any recruit field on the linked ticket. A new month's Sheet is created on its first morning. Unchanged months are left alone, so an edit typed into a managed cell stays until that month's data changes. Changes made during the day appear the next morning, or at once with **Sync now**, which rewrites every month. If the morning run fails, the next 15-minute call retries it until it succeeds (up to about 10:45 am Eastern), and a HubSpot rate limit is retried within the run.

The public application site is a separate deployment. For an immediate reconciliation request after its successful HubSpot submission, configure a separate random 32+ character **APPLICATION_SHEETS_NOTIFY_SECRET** in both servers, then have the submission server POST to `/api/applications/sheets/notify` with `Authorization: Bearer <notification secret>`. No applicant body is required or accepted as source data. The hook follows the same once-a-morning rule as the cron. It is not installed in the external application site.

## Files, rows and recovery

Each Eastern calendar month has one native Google Sheet named `MM-YY Applications` in Chandler's My Drive, also visible in Google Sheets. It has all weekly tabs for that month, Monday–Sunday clipped at month boundaries (for example November 2026 starts with Week 1 (01-01)). The empty current month is created automatically. Prior months remain separate and are refreshed while their submissions remain in the authoritative report.

Every HubSpot application note ID has one row, including repeat submissions by the same person. Columns include submitted time in Eastern, applicant information, requirement outcomes and private flags, current stage, the latest Approve/Deny decision, HubSpot links, `CRM:` columns with the linked ticket as it is now (every CRM-editable field, plus email, phone, recruiter, when the current stage began and when the record last changed), and all parsed question/answer fields. The submitted answers keep what the applicant entered; the `CRM:` columns follow later edits. Photo ID is only an attached/not-attached indicator; no ID images or expiring download links are copied. Applicant text is written as literal strings, never executable formulas. Each monthly file is shared once as an editor with sarah@lgcyap.com and carlos@fam1life.net, with Google's email notice. A refused share does not stop the rows syncing. It is shown in the panel and retried each morning after 9 am or with Sync now. See [Sharing](sign-in-sheets.md#sharing).

The synchronizer manages the generated weekly tabs and table columns. Do not add manual notes inside those columns: sync replaces their contents. Additional columns to the right are left alone. Application question changes can add managed columns, so put independent manual work in a separate tab. Spreadsheet styling and filter ranges are maintained by the sync.

A two-minute DB lease serializes the jobs. The Google transport has a shared 50-second request budget. File IDs are saved before content writes, and a Drive appProperties marker recovers a file created before a crash. Repeated notifications and ambiguous content-write responses replace rows deterministically rather than appending duplicates. Ambiguous duplicate monthly files cause an error for investigation. Partial HubSpot results, incomplete ticket reads and failed review reads never replace a workbook. The strict Sheets source reader uses ID keysets past the dashboard's 2,000-note display limit, freezes its creation-time upper bound and rejects inconsistent totals or incomplete association/ticket batches. It preserves complete answers rather than applying dashboard display truncation. Provider errors and OAuth codes/tokens are not logged or returned in status responses.

If Google access is revoked, the panel reports a failed sync and keeps the previous successful time. Reconnect Google Sheets and use Sync now. Revoking the app in Google Account settings stops future access; it does not delete monthly Sheets. No automated deletion or extra sharing is performed.

## Signed-in recruits
The same Chandler OAuth connection also authorizes monthly `MM-YY Recruits` reports in Event Attendance → Signed in. These include sign-in contact details, attendance and imported-list dates, source/license answers, current stage, review decision, the same `CRM:` columns and HubSpot links. Recruits has independent file markers, monthly state and job leases, so it cannot replace Applications files. Connecting from Event Attendance returns there and immediately starts the Recruits job. See [Recruits report setup](sign-in-sheets.md).
